Home Bakery Order Tracker

What the app does, how it handles the bakery rules, and how to start it.

Start the app

  1. Open this folder in File Explorer.
  2. Click the folder address bar, type powershell, and press Enter.
  3. In the window that opens, type python app.py and press Enter.
  4. Open http://127.0.0.1:8000 in your browser.

Keep the black command window open while you use the app. To stop it, click that window and press Ctrl+C.

If port 8000 is already in use, start with python app.py 8001 and open http://127.0.0.1:8001.

What is included

  • On first start, the app imports existing_orders.csv and InstagramOrders_Monday.html through InstagramOrders_Sunday.html if you place your own files beside app.py. This public copy does not include customer data.
  • Every new order, change, and cancellation appears in the inbox for the baker to accept or decline.
  • Accepted orders, pickup dates, product values, oven time, helper bookings, and recent decisions appear on the same page.
  • You can add later Instagram DMs by entering them in “Record a new order request”. Use “Manage” on an accepted order to record a change or cancellation request.

Order information stays on this computer in bakery.db. The database is created locally and is excluded from GitHub.

Order states and actions

New message → Pending
  Accept (when notice and oven rules pass) → Accepted order
  Decline → Declined request

Accepted order → Change request → Pending
  Approve → Updated accepted order
  Decline → Original order stays accepted

Accepted order → Cancellation request → Pending
  Approve → Cancelled order
  Decline → Original order stays accepted

Accepted order → On pickup day or later, mark picked up → Picked up

Helper available → Book at least 2 days ahead → Adds 4 oven hours for $100
  Remove booking only when accepted orders still fit the 8-hour limit

Every request decision is recorded in the recent activity list. A request that breaks a rule stays pending until the baker declines it or fixes the schedule first.

Information the app stores

  • Orders: reference, customer, product, quantity, pickup date, status, source, and note.
  • Requests: received day and time, customer, original message, request type, linked order, requested item, pickup date, and decision status.
  • Helper bookings: pickup day, booking day, and active or removed status.
  • Activity: date and time plus a short record of each decision.

How the bakery rules are applied

  • One order contains one product: cupcakes or cake.
  • Cupcakes cost $40 per dozen and take 30 minutes per dozen in the oven. Cake costs $120 each and takes 2 hours.
  • Accepted orders are counted against an 8-hour oven limit on their pickup day. The schedule shows the oven time used.
  • A helper costs $100 for one pickup day and adds 4 hours. Book a helper at least 2 days ahead; the schedule then shows the higher 12-hour limit.
  • Orders, changes, cancellations and helper bookings need at least 2 days’ notice. The app flags a request that is too late, past its pickup date, over capacity, or waiting on an earlier order decision.
  • For an order change, the app checks the revised oven load. If a cancellation is declined, the original accepted order stays on the schedule.
  • Pickup time is shown as 5:00 PM. Baking time is planned on the pickup date.

The app checks these fixed rules and shows the baker the result. It does not accept, reject, or alter an order on its own.

Built to stay simple

The app uses one Python file, app.py, and Python’s built-in libraries only. It does not use Node.js, npm, or AI. The local server listens on this computer at 127.0.0.1; it does not upload bakery data to a website.
